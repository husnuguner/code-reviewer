## Naming is context, not a finding
Every `<Verb><Entity>`, kebab-case, snake_case, `UPPER_SNAKE`, trailing-`_` or file-name shape named in these skills is **descriptive** — it shows what the house pattern looks like. Never raise a finding because an identifier, file name, route segment, constant or response key is spelled, cased or ordered differently while the code works; not even to align it with a sibling. A name is a finding only when it states something false about the thing it names (a `get-*` step that writes, a type reused under a name that no longer describes its contents).

Three naming rules are functional rather than cosmetic and still hold:
- a helper service named `<ModelName>Service` shadows the framework's per-model repository and breaks `query.graph`;
- renaming an existing step id changes the persisted ids of in-flight executions;
- a module key must be unique project-wide, or containers collide silently.

## Rules that hold in every layer
- POST for every mutation. Flag any `export const PUT` / `PATCH`; updates are POST to `/:id`
- Every `if` has a brace block — flag single-line `if (x) return;` / `if (x) continue;`
- One object parameter for steps, workflows, helpers and provider methods. Positional only for one or two natural scalars (`configOf(plan)`)
- Statuses, events and types are TS `enum`s or exported constant sets. Flag string-literal unions and `as const` objects standing in for an enum (the single accepted `as const` is a Zod schema map keyed by an enum). String literals are allowed only for values owned by an external system
- No hardcoded data, labels or config that could change — it comes from the DB or an API. Structural text is fine; dynamic data is not
- `MedusaError` from `@medusajs/framework/utils`, never a plain `Error` (a plain error surfaces as a 500). Code choice: `NOT_ALLOWED` for a state or business rule, `INVALID_DATA` for malformed input, `NOT_FOUND` for a missing row, `CONFLICT` for an in-flight hit a retry may clear, `UNAUTHORIZED` for a missing identity. Message shape: subject with its id, its current state, a semicolon, then what would be required
- Formatting is Prettier's job (width 100, single quotes, `trailingComma: es5`, `arrowParens: avoid`) and lint's: do **not** raise formatting findings, and flag a diff that reformats surrounding code it did not need to touch
- Relative imports. No `import type`. Import from `@medusajs/framework/*` and `@medusajs/core-flows`, never the legacy `@medusajs/utils` or `@medusajs/medusa/core-flows`
- `export default` only for artifacts Medusa loads by file (module `index.ts`, model, provider class, loader, subscriber function, job function; route handlers are named exports). Everything else is a named export
- Migrations are generated by the user: a model change needs a "migration required" note. Flag any hand-written or hand-edited file under `migrations/`
- Dead code is a finding: unused exports/consts/imports, `console.log` (use the injected `Logger`), orphaned constants left after a refactor, commented-out code and leftover scaffolding
- Added tests are a convention violation unless the change explicitly asked for them

## Type safety
- No `any` / `Record<string, any>` where a real type is knowable; no `as never` or `as unknown as X` used to silence tsc rather than model the data
- Flag a cast that narrows an already-loose framework type (e.g. a `query.graph` result) and thereby *forces* further casts downstream — the first cast adds no safety and one cast spawning another is the smell. A cast must model a real type (`Pick<Dto, …>`)
- Exported functions carry explicit return types. No floating promises unless the fire-and-forget is intentional
- `tsc --noEmit` and `eslint` must stay clean: flag a `// eslint-disable` or `@ts-ignore` with no reason on the line above it

## Where logic lives
| Logic | Belongs in |
|---|---|
| Generated CRUD, multi-model transactional write, orchestration of injected helpers | module service |
| Pure domain math, config readers, sanitizers | module `utils/` |
| Anything that reads or writes **another** module | a workflow step |
| A guard that throws | a `validate-*` step, never a `transform` |
| Lifecycle legality | the module's state machine — never restate a status list elsewhere |
| Outbound call to an external system | a provider behind a provider facade service |
| Request shaping, ownership gate, actor extraction | the route |
| Idempotency, lock, retry, timeout for event handling | the `SubscriberHandler` base class |

Dependency direction: `src/api` → workflows, modules, common. `src/subscribers` and `src/jobs` → workflows, modules, common. Never api → subscribers or jobs; never workflows → api; module → module only through workflow steps and links. Flag any import crossing these.

## Cross-file consistency
Sibling features follow one pattern — file layout, return shapes, hook signatures, teardown style. When two things do the same job in different shapes, the newer one is the finding: name the sibling it should have matched.

## DRY gate (before recommending any extraction)
Duplication is cheaper than the wrong abstraction. Flag *true* duplication only:
- **Shared meaning, not shared syntax** — two blocks that look alike but change for different reasons are incidental; leave them
- **Three strikes** — two copies can wait; recommend extraction at the third copy of the same concept
- **Naming test** — if the extracted unit could only be called `Generic`/`Common`/`Util`/`Base`, the domain concept is not real yet
- **Independence test** — if one copy must be changeable without reading the others, the duplication is buying local reasoning
- Genuine hits: the same concept implemented twice (one flow refactored into steps while its sibling still inlines the same logic), repeated magic constants, copy-pasted blocks that always change together
